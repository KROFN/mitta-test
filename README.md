# Митта — speculative website concept

Неофициальная демонстрационная версия сайта мебельного магазина «Митта» в Бологое. Проект собран как статический multi-page сайт без build-step и предназначен для презентации концепции.

## Структура

- `/` — главная
- `/catalog/` — каталог
- `/product/<slug>/` — карточки товаров
- `/store/` — шоурум
- `/delivery-payment/` — доставка и оплата
- `/contacts/` — контакты
- `/assets/` — стили, JS и изображения
- `/docs/` — fact audit, unresolved facts и implementation notes

## Локальный запуск

Нужен обычный статический HTTP-сервер. Например:

```bash
python -m http.server 8080
```

После этого откройте `http://localhost:8080/`.

Не открывайте HTML через `file://`: для корректной проверки маршрутов используйте HTTP-сервер.

## Deployment note

Nested routes используют каталоги с собственным `index.html`. CSS/JS подключаются относительными путями, а `site.js` автоматически определяет base path, поэтому одна и та же сборка работает как в корне домена, так и в GitHub Pages project-subpath вроде `/mitta-test/`.

## Demo safety

Страницы содержат `noindex,nofollow,noarchive`. Это концепт, а не официальный production-сайт. Перед production-публикацией необходимо перепроверить сведения из `/docs/UNRESOLVED_FACTS.md` и права на использование фотографий.
## GitHub Pages

Сборка поддерживает публикацию как GitHub Pages project-site в подпапке репозитория. CSS/JS подключаются относительными путями, а `site.js` автоматически определяет base path (например, `/mitta-test`) и добавляет его к внутренним маршрутам и изображениям.

Для `KROFN/mitta-test`: Settings → Pages → Deploy from a branch → `main` / `(root)`. Файл `.nojekyll` уже находится в корне. На custom domain пользовательского Pages-сайта проект открывается по `https://krofn.ru/mitta-test/`.



## Статическая генерация страниц (SSG)

`node scripts/build-pages.js` генерирует 21 HTML-страницу: главную, каталог, магазин,
доставку, контакты и 16 товарных URL (15 моделей + алиас `/product/vendetta/`).
Генератор использует существующие модели данных и шаблоны из `assets/site.js`:
второго списка товаров нет. Нужен только Node.js, сторонние пакеты не требуются.

- HTML содержит фактическую разметку товаров, `h1`, заголовок, описание,
  Open Graph и JSON-LD Product. У неподтверждённых цен намеренно отсутствует
  разметка `Offer`/`price`.
- В браузере `site.js` распознаёт готовый HTML, **не заменяет `#app`** и
  навешивает обработчики меню, фильтров и фотогалереи.
- Относительные URL ассетов и навигации работают как в корне домена, так и
  в project-subpath GitHub Pages.
- Статические страницы остаются с `noindex,nofollow,noarchive`: это
  неофициальная демонстрация. До публикации необходимо сверить ассортимент,
  цены, адрес, отзывы и права на изображения.

Для production-сборки с подтверждённым доменом:

```bash
SITE_URL=https://example-shop.ru node scripts/build-pages.js
node scripts/test-pages.js
```

`SITE_URL` задаёт **публичный канонический адрес** (может содержать подпуть);
по нему генерируются `canonical`, `og:url`, абсолютные `og:image` и
ссылки внутри JSON-LD. Для товаров без фотографии `og:image` опускается.

Только после утверждения контента и прав можно явно включить индексирование:
`SITE_URL=https://example-shop.ru INDEXABLE=1 node scripts/build-pages.js`.
Без корректного HTTPS `SITE_URL` такой запуск запрещён.

Если изменяются товары, шаблоны или маршруты в `assets/site.js`, после
редактирования необходимо заново запускать генератор и тесты. Ручные
изменения в генерируемых `index.html` будут затёрты. Для будущей CMS /
Google Sheets потребуется отдельный надёжный контур импорта и валидации.
